# 07 · 常见问题与排错

## 7.1 先做这 5 项检查

```bat
:: 1. 进程和端口
netstat -ano | findstr ":9000 :9001"
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='silo.exe'\" | Select-Object ProcessId,CommandLine | Format-List"

:: 2. 健康检查
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:9000/minio/health/live

:: 3. 未签名根路径应返回 403
curl -s http://127.0.0.1:9000/

:: 4. 控制台应返回 200
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:9001/

:: 5. 凭据是否有效（SigV4 列桶）
curl -s --aws-sigv4 "aws:amz:us-east-1:s3" --user "minioadmin:minioadmin" http://127.0.0.1:9000/
```

也可以直接跑：

```bat
scripts\check-server.bat
```

## 7.2 构建与运行

### `UnsupportedClassVersionError` / Spring Boot 启动失败

现象：

```text
java.lang.UnsupportedClassVersionError: ... class file version 61.0,
this version of the Java Runtime only recognizes class file versions up to 52.0
```

原因：Maven/Java 使用了 JDK 8。

处理：

```bat
scripts\build.bat
scripts\demo.bat object
```

脚本会调用 `scripts\env-java21.bat` 把 `JAVA_HOME` 指向 JDK 21。也可以手动：

```bat
set JAVA_HOME=D:\ProgramFiles\JAVA\graalvm-jdk-21.0.7
set PATH=%JAVA_HOME%\bin;%PATH%
mvn -v
```

### `Cannot access okhttp3.HttpUrl` / `找不到 okhttp3.Response`

原因：MinIO 8.6.0 的 POM 引用 OkHttp 5 的多平台门面 jar，Maven 没有拿到 JVM 类。

处理：`pom.xml` 已显式加入：

```xml
<dependency>
  <groupId>com.squareup.okhttp3</groupId>
  <artifactId>okhttp-jvm</artifactId>
  <version>5.1.0</version>
</dependency>
```

不要删除这个依赖，也不要只依赖 `okhttp` 5.1.0（它只有元数据）。

### IntelliJ 报语言级别/运行时不匹配

- Project Structure → Project SDK：JDK 21
- Project language level：21
- Settings → Build Tools → Maven → Runner → JRE：JDK 21
- 运行 `Main` 时 Program arguments 填 `--demo=object`

### `mvn` 仍显示 Java 1.8

`mvn -v` 看 Java version。若仍为 1.8，说明没有经过 `env-java21.bat` 或 `JAVA_HOME` 没生效。检查：

```bat
echo %JAVA_HOME%
where java
```

## 7.3 HTTP / S3 错误

### `403 Forbidden` / `AccessDenied`

可能原因：

- 请求没有签名（直接 curl 根路径是正常现象）。
- 桶是私有的，匿名访问被拒绝。
- 预签名 URL 过期。
- IAM 策略缺少 `s3:GetObject`/`s3:PutObject`。
- 时钟偏差导致签名无效（通常表现为 `SignatureDoesNotMatch`）。

排查：

```bat
mcli anonymous get silo/<bucket>
mcli ls silo/<bucket>
mcli stat silo/<bucket>/<key>
```

### `SignatureDoesNotMatch`

- 系统时间偏差 > 15 分钟 → 同步 Windows 时间。
- endpoint 写错（例如用了控制台 9001）。
- 反向代理改写了 Host/路径/查询参数。
- 客户端 region 与服务端不一致（MinIO/Silo 默认 `us-east-1`）。
- 预签名 URL 被二次 URL 编码。

### `404 NoSuchKey` / `NoSuchBucket`

- Key 大小写/前缀错误。
- 对象在版本化桶中被 Delete Marker 覆盖。
- 桶名拼错。
- 预签名 URL 指向了错误的对象。

### `409 BucketNotEmpty`

桶里还有对象或版本。版本化桶需要删除所有版本和 Delete Marker：

```bat
mcli rm --recursive --force --versions silo/<bucket>
mcli rb --force silo/<bucket>
```

### `409 BucketAlreadyExists` / `BucketAlreadyOwnedByYou`

桶名已被占用；换一个唯一名称。Demo 会先清理同名学习桶。

### `400 InvalidBucketName`

桶名只能包含小写字母、数字、点和连字符，长度 3–63，不能以点/连字符开头结尾。

## 7.4 生命周期相关

### `InvalidArgument ... XML ... did not validate against our published schema`

本机 Silo 的已知行为：

- 仅含 `AbortIncompleteMultipartUpload` 的规则会被拒绝。
- 把 abort 与 `Expiration` 合并可以通过配置校验。
- 即使配置成功，`getBucketLifecycle` 也可能不返回 abort 动作。

处理：按 `LifecycleDemo` 的组合写法；以实际实现行为为准。

### 删除后 `getBucketLifecycle` 返回 null

SDK 8.6.0 对 `NoSuchLifecycleConfiguration` 返回 `null`，不抛异常。用 `config == null` 判断，而不是 `catch`。

### 配置成功但对象没有立即删除

生命周期由后台 scanner 异步执行，可能分钟到小时级。不要用“立即过期”做集成测试断言。

### 用 curl 直接 PUT 生命周期返回 `MissingContentMD5`

S3 的 lifecycle PUT 需要 `Content-MD5` 或 checksum 头。用 SDK 会自动处理；手写 curl 时：

```bat
openssl dgst -md5 -binary lifecycle.xml | openssl base64 -A
curl -H "Content-MD5: <base64>" ...
```

## 7.5 对象锁相关

### `InvalidRequest` / `AccessDenied` 删除被拒

- 对象在 GOVERNANCE/COMPLIANCE 保留期内。
- 有 Legal Hold。
- 删除时没有带 `versionId`。
- 没有 `bypassGovernanceMode(true)`（GOVERNANCE）。

处理：先 `disableObjectLegalHold`；GOVERNANCE 用 bypass；COMPLIANCE 只能等到期。

### 建桶后无法开启对象锁

对象锁必须在 `makeBucket` 时设置 `objectLock(true)`，事后不能补开。删掉重建（确认无数据）。

### 桶删不掉

- 还有版本/Delete Marker/Legal Hold。
- COMPLIANCE 未到期。
- 用 `mcli rm --versions --recursive --force`，Legal Hold 先 clear。

## 7.6 加密相关

### `SSE-C operations must be performed over a secure connection.`

SDK 在 HTTP endpoint 上本地拒绝 SSE-C。处理：

- 使用 HTTPS endpoint；或
- 按 [08-SSE-C-HTTPS实验](08-SSE-C-HTTPS实验.md) 启动 TLS 实例。

### `Requests specifying Server Side Encryption with Customer provided keys must be made over a secure connection.`

Silo 服务端同样强制 HTTPS。不是密钥错误，是传输不安全。

### 无 key 读取返回 400

正常行为：SSE-C 对象必须携带相同的 `x-amz-server-side-encryption-customer-*` 头。

### 密钥丢失

SSE-C 数据不可恢复。生产必须使用 KMS/密钥托管和备份。

## 7.7 分片与 ETag

### ETag 比较失败

ETag 可能带引号：

```text
"0cdaffc8e69cab00470bf84bc31f305b-4"
```

比较前：

```java
String normalized = etag.replace("\"", "");
```

### 分片上传失败：part size too small

最小分片 5 MiB（最后一片除外）。不要用 1 MiB 分片。

### ETag 不是整个文件的 MD5

分片上传的 ETag 是分片 MD5 的组合，带 `-N` 后缀。需要内容校验时用额外哈希（如 SHA-256）存入元数据。

## 7.8 预签名

### `IllegalArgumentException: expiry must be minimum 1 second to maximum 7 days`

预签名最长 7 天，缩短有效期或改用临时凭据/代理。

### URL 在 cmd 中被截断

URL 含 `&`，在 cmd 中必须整体加双引号：

```bat
curl -s -o NUL -w "%{http_code}" "<presigned-url>"
```

### 浏览器 PUT 预签名失败（CORS）

浏览器直接 `fetch` 预签名 PUT 会触发对象存储 CORS。页面只展示 URL，用 curl 验证；生产可在桶上配置 CORS 规则。

## 7.9 Windows 环境

### 控制台中文乱码

- 脚本已 `chcp 65001` 并加 `-Dstdout.encoding=UTF-8`。
- 手动运行 jar 时加：
  ```bat
  java -Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8 -jar ...
  ```
- IntelliJ Console 设置为 UTF-8。

### `localhost` 连接失败，`127.0.0.1` 正常

`localhost` 可能解析为 IPv6 `::1`，而服务只监听 IPv4。统一使用 `127.0.0.1`。

### 端口 8080 被占用

```bat
set SERVER_PORT=8081
scripts\run-web.bat
```

### 上传超过 100MB 返回 413

`application.yml` 限制 100MB/105MB；调整：

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 200MB
      max-request-size: 210MB
```

## 7.10 测试相关

### 测试全部 skipped

没有设置 `MINIO_IT=true`。用：

```bat
scripts\test-it.bat
```

### 测试连接失败

- Silo 未启动或 endpoint 不对。
- 凭据错误。
- 8080/随机端口被防火墙拦截（WebApiIT 使用随机端口）。
- 先用 `scripts\check-server.bat` 验证。

### 清理失败

对象锁桶可能有 Legal Hold 或 COMPLIANCE。测试只用短 GOVERNANCE；如果手动创建了 COMPLIANCE 桶，只能等到期或使用有权限的 bypass（COMPLIANCE 不可 bypass）。

## 7.11 实用诊断命令

```bat
:: 进程命令行
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='silo.exe'\" | Select ProcessId,CommandLine"

:: 端口
netstat -ano | findstr ":9000 :9001 :8080 :9443 :9444"

:: 健康
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:9000/minio/health/live
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:9000/minio/health/ready

:: 签名请求
curl -s --aws-sigv4 "aws:amz:us-east-1:s3" --user "minioadmin:minioadmin" http://127.0.0.1:9000/

:: SDK 日志（临时）
:: 在 application.yml 把 io.minio 调成 DEBUG，排障后恢复 WARN
```

## 7.12 不要做的事

- 不要手工删除/修改 `.minio.sys` 或数据目录中的对象文件。
- 不要用 root 凭据做生产压测/应用连接。
- 不要在 HTTP 上使用 SSE-C。
- 不要对生产桶随意开启 COMPLIANCE 对象锁。
- 不要把默认凭据、SSE-C 密钥、预签名 URL 提交到 Git。
