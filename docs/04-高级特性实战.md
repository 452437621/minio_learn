# 04 · 高级特性实战

本篇把版本、对象锁、生命周期、策略、加密、分片、通知/复制串起来，并记录在本机 Silo 上的实测行为。

## 4.1 版本控制

### 开启与挂起

```java
client.setBucketVersioning(SetBucketVersioningArgs.builder().bucket(b)
        .config(new VersioningConfiguration(
                VersioningConfiguration.Status.ENABLED, null))
        .build());
```

- 开启后，每次 PUT 生成新 `versionId`。
- 删除（不带 versionId）生成 Delete Marker，当前版本变为“不存在”。
- 挂起（SUSPENDED）后，新写入使用 `null` 版本，覆盖同一个 `null` 版本。
- 版本控制不能“关闭”，只能挂起。

### 典型操作

| 操作 | 结果 |
|---|---|
| `GET` 不带 versionId | 读当前版本；若当前是 Delete Marker 则 404 |
| `GET` 带 versionId | 读指定历史版本 |
| `DELETE` 不带 versionId | 生成 Delete Marker |
| `DELETE` 带 versionId | 真正删除该版本 |
| `listObjects(includeVersions=true)` | 返回所有版本和 Delete Marker |

### 恢复误删

1. 列出所有版本，找到 Delete Marker 之前的历史版本。
2. 用该 `versionId` GET 验证内容。
3. 删除 Delete Marker（按 versionId），让历史版本重新成为当前版本；或复制历史版本为新的当前版本。

### 清理

版本化桶不能直接 `removeBucket`。必须删除所有版本和 Delete Marker，再删桶。见 docs/03 的清理代码。

## 4.2 对象锁（WORM）

### 两种保留模式

| 模式 | 行为 | 适用 |
|---|---|---|
| GOVERNANCE | 有 `bypassGovernanceMode` 权限者可以提前删除/缩短 | 内部合规、防误删 |
| COMPLIANCE | 到期前任何人都不能删除/修改，root 也不行 | 法规、审计、不可抵赖 |

### 关键规则

- 必须在**建桶时**开启：`MakeBucketArgs.objectLock(true)`；事后不能补开。
- 对象锁桶自动启用版本控制。
- 可以设置桶级默认保留（如 GOVERNANCE 1 天），新对象自动继承。
- 可以给单个对象/版本设置 retention 或 legal hold。
- Legal Hold 与保留期限独立；有 legal hold 时，即使 GOVERNANCE 到期也不能删除，必须先关闭。
- 删除受保护版本必须带 `versionId` + `bypassGovernanceMode(true)`（GOVERNANCE）或等到期（COMPLIANCE）。

### 本机实测

- 创建对象锁桶、默认 GOVERNANCE 1 天、legal hold 开关、retention 读取均正常。
- 不带 bypass 删除受保护版本返回 `InvalidRequest` / HTTP 400（不是 403）。不同版本/实现可能返回 `AccessDenied`，测试应断言“被拒绝”而不是固定错误码。
- `bypassGovernanceMode(true)` 删除成功。

### 风险

- 对生产桶误开 COMPLIANCE 可能导致数据在保留期内无法删除，务必先用 GOVERNANCE 验证。
- 对象锁不是备份；它防止删除/篡改，但不防止磁盘故障。

## 4.3 生命周期

### 规则类型

| 动作 | 作用 |
|---|---|
| `Expiration` | 当前版本在 N 天后过期删除 |
| `NoncurrentVersionExpiration` | 非当前版本在 N 天后删除 |
| `AbortIncompleteMultipartUpload` | N 天后清理未完成的分片上传 |
| `Transition` | 转换存储类型（需要目标存储层） |

### 配置示例

```java
LifecycleRule expire = new LifecycleRule(
        Status.ENABLED, null,
        new Expiration((ZonedDateTime) null, 1, null),
        new RuleFilter("tmp/"), "expire-tmp", null, null, null);

LifecycleRule noncurrent = new LifecycleRule(
        Status.ENABLED, null, null,
        new RuleFilter("docs/"), "expire-noncurrent",
        new NoncurrentVersionExpiration(1), null, null);
```

### 本机 Silo 实测差异

1. **abort-only 规则被拒绝**：只含 `AbortIncompleteMultipartUpload` 的规则返回 `InvalidArgument`。
2. 把 abort 与 `Expiration` 放在同一规则可以通过配置校验，但 `getBucketLifecycle` 不返回 abort 动作，只保留 Expiration。
3. 删除生命周期后，SDK `getBucketLifecycle` 返回 `null`，不抛 `NoSuchLifecycleConfiguration`。
4. 生命周期是异步扫描：配置成功不代表对象立刻被删除，实际可能分钟到小时级；测试只做配置往返。

> 这些差异说明：S3 兼容不等于每个扩展行为完全一致。生产上要在目标实现上做集成验证。

## 4.4 桶策略

### 匿名只读（最小示例）

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"AWS": ["*"]},
    "Action": ["s3:GetObject"],
    "Resource": ["arn:aws:s3:::learn-policy/*"]
  }]
}
```

- 只允许 `GetObject`，不允许 `ListBucket`。
- 设置后匿名 GET 对象 200；删除策略后 403。
- 生产应加 `Condition` 限制 TLS、来源 IP、VPC endpoint；敏感数据不要用匿名策略。

### 前缀级授权

```json
"Resource": ["arn:aws:s3:::my-bucket/public/*"]
```

只开放 `public/` 前缀，其他对象保持私有。

### 常见错误

- Resource 写成 `arn:aws:s3:::bucket`（缺 `/*`）→ 只能匹配桶本身，不匹配对象。
- Principal 写成 `"*"` 而不是 `{"AWS":["*"]}` → 校验失败。
- 忘删测试策略 → 数据意外公开。

## 4.5 加密

| 方式 | 密钥位置 | 需要 HTTPS | 本机可运行 |
|---|---|---|---|
| SSE-C | 客户端每次请求携带 | 是 | HTTP 下演示拦截；HTTPS 实验可完整运行 |
| SSE-S3 | 服务端/KMS 托管 | 建议 | 需要 KMS/KES 配置，未启用 |
| SSE-KMS | 外部 KMS | 是 | 需要 KMS，未启用 |

### SSE-C 要点

- 32 字节 AES 密钥；每次 PUT/GET/HEAD 都要带同样的密钥。
- SDK 写用 `.sse(ssec)`，读用 `.ssec(ssec)`。
- 密钥丢失 = 数据永久不可读。
- 必须 HTTPS；HTTP 下 SDK 本地就拒绝，Silo 服务端也拒绝。
- 完整实验：启动一个临时 TLS Silo（9443），生成自签名证书和 truststore，运行 `--demo=ssec --learn.minio.endpoint=https://127.0.0.1:9443`。见 docs/08（已实测通过）。

### 生产建议

- 优先使用 SSE-KMS/SSE-S3，把密钥管理交给专业系统。
- 必须使用 TLS；SSE-C 尤其如此。
- 记录密钥轮换和恢复流程；不要打印/提交密钥。

## 4.6 分片上传

### 关键数字

- 分片最小 5 MiB，最大 5 GiB。
- 最多 10000 片。
- 单次 PUT 最大 5 GiB，单对象最大 5 TiB。
- 分片 ETag 带 `-N` 后缀，不是整个对象的 MD5。

### SDK 行为

```java
client.putObject(PutObjectArgs.builder()
        .bucket(b).object("big/20m.bin")
        .stream(in, 20L * 1024 * 1024, 5L * 1024 * 1024)
        .build());
```

- SDK 自动完成 `CreateMultipartUpload → UploadPart → CompleteMultipartUpload`。
- 8.6.0 没有公开的低层 multipart API；需要手工控制分片时用 AWS SDK v2。
- 上传失败会留下未完成分片，占用空间；用生命周期 abort 规则清理。

### 验证

- 20 MiB / 5 MiB → ETag `"...-4"`。
- Range GET 最后 1 KiB 成功。
- 控制台/mcli `stat` 查看大小和 ETag。

## 4.7 标签与元数据

| 类型 | 写入方式 | 用途 |
|---|---|---|
| User Metadata | `x-amz-meta-*` / `.userMetadata(Map)` | 业务属性、审计信息 |
| Object Tags | `.tags(Map)` / `setObjectTags` | 生命周期、权限、成本、分类 |
| Content-Type | `.contentType(...)` | 浏览器预览/下载行为 |
| Cache-Control 等 | `.headers(Map)` | HTTP 缓存策略 |

标签最多 10 个；更新是覆盖式。不要把敏感信息放进元数据/标签（它们通常可被有读权限的人看到）。

## 4.8 通知与复制（单机仅文档）

### 事件通知

S3 事件通知可以把 `s3:ObjectCreated:*`、`s3:ObjectRemoved:*` 等事件推到 webhook、AMQP、Kafka、Redis 等目标。需要：

1. 在服务端配置通知目标（环境变量或配置文件）。
2. 用 `mc event add` 把桶事件绑定到目标 ARN。
3. 消费者幂等处理（事件可能重复/乱序）。

单机 Silo 默认没有通知目标，本项目不提供可运行 Demo。

### 跨站复制

复制用于异地容灾/多活：

- 源桶和目标桶都要开启版本控制。
- 配置复制规则（前缀、标签、删除标记复制、existing object replication）。
- 需要网络、凭据、目标 endpoint；单机环境无法完整演示。

生产上复制不是备份的替代品：误删/勒索会同步复制；仍需独立备份和保留策略。

## 4.9 限额与设计约束

| 约束 | 影响 |
|---|---|
| 单 PUT 5 GiB | 大文件必须分片 |
| 分片 5 MiB 起 | 小文件不要强行分片 |
| 10000 片 | 超大对象需要更大分片 |
| 预签名 7 天 | 长周期访问要用临时凭据/代理 |
| 标签 10 个 | 复杂分类应放数据库/元数据服务 |
| 版本无限增长 | 必须配生命周期清理非当前版本 |
| 匿名策略全局生效 | 误配置会公开数据 |

## 4.10 最佳实践清单

- 桶名/前缀按业务和环境规划，便于生命周期和权限控制。
- 生产桶默认私有，匿名策略只用于明确的公共资源。
- 开启版本控制 + 生命周期清理，平衡可恢复性与成本。
- 大文件使用分片，失败重试要幂等。
- 所有敏感数据使用 TLS；SSE-C 必须 TLS。
- 对象锁先用 GOVERNANCE 验证，COMPLIANCE 谨慎。
- 监控 4xx/5xx、容量、未完成分片、复制延迟。
- 定期做恢复演练，而不是只做备份。
