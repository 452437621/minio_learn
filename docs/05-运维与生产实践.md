# 05 · 运维与生产实践

> 本机是单机单盘学习环境。本篇中的分布式、KMS、复制、通知、TLS 终止等内容是生产知识，**不能**在当前实例上完整运行；可运行的部分已在 Demo 中覆盖。

## 5.1 单机与分布式

| 部署 | 特点 | 适用 |
|---|---|---|
| 单机单盘 | 最简单，无冗余 | 学习、临时测试 |
| 单机多盘 | 纠删码，磁盘级冗余 | 小规模、边缘 |
| 多节点多盘 | 节点级冗余、横向扩展 | 生产 |

MinIO/Silo 的分布式模式通常要求：

- 每个节点提供相同的磁盘数量/容量。
- 使用专用数据盘，不要把数据目录放在系统盘或网络盘（除非明确支持）。
- 节点时间同步（NTP），否则签名会失败。
- 通过负载均衡/反向代理暴露 S3 API，控制台单独暴露。
- 规划故障域：同一对象的数据块/校验块尽量分散到不同节点/机架。

## 5.2 纠删码与容量

假设 4 节点 × 4 盘，`EC:4`（4 数据 + 4 校验）：

- 可以容忍任意 4 个块丢失。
- 可用容量约为裸容量的 50%。
- 写放大和 CPU 开销随校验块增加。

实际可用容量、冗余级别取决于 `silo server` 的磁盘布局和纠删码配置。不要用 RAID 再叠加纠删码而不做容量/故障域评估。

### 自愈（Healing）

- 磁盘/节点恢复后，Silo 会在后台重建缺失块。
- 用 `mcli admin heal`（如果客户端支持）或控制台查看 healing 状态。
- 自愈期间性能可能下降；不要在高负载时频繁重启节点。

## 5.3 数据目录

本机数据目录：

```text
D:\ProgramFiles\silo_20261112000000.0.0_windows_amd64\minio\
└─ .minio.sys\
```

规则：

- 不要手工编辑/删除 `.minio.sys`。
- 不要用文件系统工具“修复”对象文件。
- 备份/迁移时整体复制数据目录，或使用 `mcli mirror`/复制。
- 升级前先停服务并做完整备份。

## 5.4 TLS

生产必须使用 TLS。Silo/MinIO 支持：

```bat
silo.exe server D:\data --address :9000 --console-address :9001 --certs-dir D:\certs
```

`D:\certs` 下放置：

```text
public.crt
private.key
```

常见做法：

- 用受信任 CA 签发证书（Let's Encrypt、企业 CA）。
- 证书 SAN 必须包含客户端访问使用的主机名/IP。
- 反向代理（Nginx/HAProxy）终止 TLS 时，确保 `Host` 头和签名一致；预签名 URL 使用对外域名。
- 控制台和 S3 API 分开域名/端口，限制控制台来源 IP。
- SSE-C 必须 HTTPS；没有 TLS 就不要使用 SSE-C。

本项目的 SSE-C HTTPS 实验使用自签名证书，仅用于本地验证，见 docs/08。

## 5.5 IAM 与凭据

### 不要用 root 凭据跑应用

`minioadmin/minioadmin` 是超级管理员。生产应：

1. 修改 root 凭据并妥善保管。
2. 为每个应用创建独立用户。
3. 只授予必要的前缀/动作。
4. 定期轮换密钥。

示例（mcli）：

```bat
mcli admin user add silo app-user app-secret
mcli admin policy attach silo readwrite --user app-user
mcli admin user list silo
```

策略应遵循最小权限：只允许需要的 bucket/prefix/action，例如只允许 `s3:GetObject`、`s3:PutObject` 到 `app-bucket/uploads/*`。

### 凭据管理

- 不要把密钥写入代码、镜像、日志、Git。
- 使用环境变量/密钥管理系统（Vault、KMS、K8s Secret）。
- 为不同环境使用不同凭据。
- 记录轮换和吊销流程。

## 5.6 监控与排障

### 健康检查

```text
GET /minio/health/live    进程存活
GET /minio/health/ready   可服务
```

本机验证：

```bat
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:9000/minio/health/live
```

### 指标

- Prometheus 指标端点（通常需要认证）：`/minio/v2/metrics/cluster`
- 控制台有 Metrics 页面。
- 关注：请求 4xx/5xx、延迟、容量、磁盘错误、healing、复制延迟、未完成分片。

### 日志与追踪

```bat
mcli admin info silo
mcli admin trace silo
```

`trace` 会显示请求头，注意脱敏；不要在生产长时间开启。

### 审计

Silo/MinIO 支持审计日志（输出到文件/webhook）。生产应开启并集中收集，记录谁在何时对哪个对象做了什么操作。

## 5.7 备份与恢复

| 方式 | 说明 | 注意 |
|---|---|---|
| `mcli mirror` | 同步到另一个 S3/目录 | 删除语义、版本、带宽 |
| 版本控制 | 防覆盖/误删 | 版本会增长，需要生命周期清理 |
| 跨站复制 | 异地容灾 | 需要版本控制、网络、凭据 |
| 快照/对象存储备份 | 云盘/存储层快照 | 与应用一致性 |
| 独立备份系统 | 备份软件/冷存储 | 定期恢复演练 |

RAID/纠删码不是备份：它们防磁盘故障，不防误删、勒索、逻辑损坏、机房故障。

恢复演练：

1. 在隔离环境恢复一个桶/前缀。
2. 校验对象数量、大小、ETag/内容。
3. 记录 RTO/RPO。
4. 验证权限和加密密钥可用。

## 5.8 升级与迁移（MinIO → Silo）

Silo 兼容 MinIO 的数据目录和 `MINIO_*` 配置。升级步骤（概念）：

1. 阅读目标版本 release notes 和兼容性说明。
2. 停服务，做完整备份（数据目录 + 配置）。
3. 替换二进制/镜像，保留数据目录和配置。
4. 启动，检查健康、控制台、桶/对象、IAM、生命周期。
5. 跑一轮读写/预签名/版本化验证。
6. 保留回滚路径（旧二进制 + 备份）。

不要跨大版本直接在生产升级；先在测试环境验证。

## 5.9 安全清单

- [ ] 修改默认 root 凭据
- [ ] 应用使用独立 IAM 用户，最小权限
- [ ] 全链路 TLS（S3 API、控制台、反向代理）
- [ ] 控制台限制来源 IP/VPN
- [ ] 桶默认私有，匿名策略有审批和回收
- [ ] 开启审计日志并集中收集
- [ ] 监控容量、错误率、未完成分片、healing
- [ ] 版本控制 + 生命周期清理
- [ ] 独立备份 + 定期恢复演练
- [ ] 密钥托管/轮换/吊销流程
- [ ] 对象锁策略经过评审（尤其 COMPLIANCE）
- [ ] 定期升级并关注安全公告

## 5.10 本机不能完整演示的内容

| 能力 | 原因 | 学习方式 |
|---|---|---|
| 分布式/纠删码冗余 | 单机单盘 | 阅读架构文档，搭建多节点实验环境 |
| KMS/SSE-S3/SSE-KMS | 未配置 KMS | 部署 KES/MinIO KMS 后实验 |
| 跨站复制 | 需要第二个集群 | 两个实例 + 网络 + 凭据 |
| 事件通知 | 未配置通知目标 | 配置 webhook/Kafka 后实验 |
| 反向代理 TLS | 未部署代理 | Nginx/HAProxy + 证书 |
| 审计日志 | 未配置输出 | 配置文件/webhook |

这些能力在单机上可以通过配置启用，但会改变本机服务状态；本项目保持只读/演示友好，不自动修改你的 Silo 配置。
